## Summary

`AssessmentViewRestController` exposes one assessment run as a REST resource at `/api/v1/assessments`.

One `POST` creates the **whole aggregate** in a single call:

- the `AssessmentView` row,
- all its `QuestionAndAnswer` rows (**composition**, saved by `CascadeType.ALL`),
- one `Answer` per Q&A (**composition**, saved by `CascadeType.ALL`).

`Customer`, `CustomerProfile` and `Question` are **associations**: they must already exist and are referenced **by id only**.

## Endpoints

| Method | URL | Params / Body | Returns |
|--------|-----|---------------|---------|
| `POST` | `/api/v1/assessments/create` | JSON body (see below) | created `AssessmentView` |

| `GET` | `/api/v1/assessments/byId` | `id` | `AssessmentView` or `null` |
| `GET` | `/api/v1/assessments/byCustomerId` | `customerId` | `List<AssessmentView>` |
| `GET` | `/api/v1/assessments/questionsAndAnswers` | `id` (assessment id) | `List<QuestionAndAnswer>` |
| `GET` | `/api/v1/assessments/score` | `id` (assessment id) | `double` (sum of `scoreContribution`) |
| `GET` | `/api/v1/assessments/count` | — | `long` |
| `DELETE` | `/api/v1/assessments/byId` | `id` | deleted `AssessmentView` or `null` |
| `DELETE` | `/api/v1/assessments/all` | — | — |

## Prerequisites (associations must exist)

Get real ids before posting:

| Entity | How to get the id |
|--------|-------------------|
| `Customer` | `GET /api/v1/customers/all` (ids are UUIDs, generated by `PopulatorDB`) |
| `Question` | `GET /api/v1/questions/all` (ids are UUIDs) |
| `CustomerProfile` | `GET /api/v1/customerProfiles/all` — `P01..P04` from `profiles.json`, or a UUID if created with `POST /api/v1/customerProfiles/create` |

`POST /api/v1/customerProfiles/create` works like the other create endpoints: `CustomerProfileService.createCustomerProfile(...)` sets a new UUID as `id` (the client does not send it) and saves the profile.

## Create an assessment (Postman)

`POST http://localhost:8080/api/v1/assessments/create` — Body → raw → JSON

### Request

```json
{
  "customer": { "id": "26256f77-06ea-4c6e-bba3-4754bced74e8" },
  "profile": { "id": "916933e0-70d5-4c52-9aa9-48840a01cc30" },
  "questionsAndAnswers": [
    {
      "question": { "id": "7504a93c-a16c-4438-a140-4ae7dd326631" },
      "answer": { "value": true },
      "scoreContribution": 1.0
    },
    {
      "question": { "id": "e0041c35-8a76-49af-8745-b9d0c128ebec" },
      "answer": { "value": false },
      "scoreContribution": 0.0
    },
    {
      "question": { "id": "813ff44d-9e58-455c-908a-b2cac485c0f5" },
      "answer": { "value": true },
      "scoreContribution": 1.0
    }
  ]
}
```

Fields **not** sent by the client (set by the service): `id`, Q&A `id`, Answer `id`, `qtyQuestions`, `timestamp` (optional — set to now if missing).

```json
    "address": "Suite 901 874 Lucius Canyon, New Fredericachester, SC 13191"
  },
  "timestamp": "2026-11-05T10:00:17.959387592Z",
  "qtyQuestions": 3,
  "profile": {
    "id": "916933e0-70d5-4c52-9aa9-48840a01cc30",
    "codeProfile": "BEGINNER",
    "name": "Beginner",
    "description": "Wants to start learning programming from scratch",
    "goal": "Learn basic programming concepts and build a first project",
    "profileAnswers": {},
    "customer": null,
    "recommendedRoadmaps": []
  }
}
```

What to notice:

- **`id`** and **`timestamp`** were generated by the service.
- **`qtyQuestions: 3`** was computed from the incoming list.
- **`customer`** and **`profile`** come back **fully loaded** from the DB — the request only had their ids.
- **`questionsAndAnswers` is not in the response**: the field is `@JsonProperty(access = WRITE_ONLY)` — accepted on input, never serialized. Read them with `/questionsAndAnswers?id=...`.
- `profile.customer` is `null` and `recommendedRoadmaps` is `[]` because this profile was created without them; that is profile data, not an assessment issue.

## What the service does — `AssessmentViewService.createAssessmentView(...)`

The controller only delegates; all logic lives in the service. Step by step:

1. **Generate the id** — `assessmentView.setId(UUID.randomUUID().toString())`; the client never sends it.
2. **Set the timestamp** — if `timestamp` is `null`, it is set to `Instant.now()`.
3. **Resolve the `Customer` by id** — the JSON only carries `{"id": "..."}`, so the service replaces that stub with the real entity from `customerRepository.findById(...)`. Unknown id → `IllegalArgumentException("Customer not found: ...")`. The customer is **referenced, not created** (association).
4. **Resolve the `CustomerProfile` by id** — same pattern with `customerProfileRepository`. Unknown id → `IllegalArgumentException("CustomerProfile not found: ...")`.
5. **Rebuild the Q&A list** — the incoming list is copied and the entity's list is reset. For each `QuestionAndAnswer`:
   - a new UUID is set as its `id`;
   - a `question.id` is **required**, otherwise `IllegalArgumentException("QuestionAndAnswer requires an existing question id")`;
   - the `Question` stub is replaced by the real entity from `questionRepository` (unknown id → `"Question not found: ..."`);
   - if the `Answer` has no id, a new UUID is set (the `Answer` is **new**, owned by the Q&A);
   - it is added with `assessmentView.addQuestionAndAnswer(...)`, which also sets `questionAndAnswer.assessmentView = this`. This is required because `QuestionAndAnswer` is the **owning side**: without it, `assessment_view_id` would be saved as `NULL`.
6. **Compute `qtyQuestions`** — the size of the rebuilt list.
7. **Save once** — `assessmentViewRepository.save(assessmentView)`. `CascadeType.ALL` on `questionsAndAnswers` saves every `QuestionAndAnswer`, and `CascadeType.ALL` on `QuestionAndAnswer.answer` saves every `Answer`.

Other service methods:

| Method | What it does |
|--------|--------------|
| `getAllAssessmentViews()` | `findAll()` |
| `getAssessmentViewById(id)` | `findById(id)`, `null` if not found |
| `getAssessmentViewsByCustomerId(customerId)` | derived query `findByCustomerId` |
| `getQuestionAndAnswersByAssessmentViewId(id)` | queries `question_and_answer` by FK (`findByAssessmentViewId`) instead of navigating the `LAZY` collection outside a transaction |
| `getTotalScore(id)` | sums `scoreContribution` of the assessment's Q&A rows (skips `null`) |
| `deleteAssessmentView(id)` | `deleteById`; Q&A rows and their answers are deleted by cascade |
| `deleteAllAssessmentViews()` | `deleteAll()` |
| `countAssessmentViews()` | `count()` |

## Notes

- **Jackson 3 and primitives**: Spring Boot 4 uses Jackson 3, which fails by default when a primitive (`int`, `double`) gets `null`. The request references `Question` by id only (no `order`/`weight`) and does not send `qtyQuestions`, which caused `Cannot map null into type int`. Fixed in `application.properties`:

  ```properties
  spring.jackson.deserialization.fail-on-null-for-primitives=false
  ```

- **Error handling**: the `IllegalArgumentException`s thrown by the service are not mapped to a `4xx` yet, so an unknown id currently returns `500`.
- **Unit test**: `DemoApplicationTests.assessmentViewWithQuestionAndAnswers` covers the same flow without JSON (create, count, score, profile, cascade delete).
